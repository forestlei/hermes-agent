# Persistent Solver — 持久求解器 v3.2

> 解决两个根本缺陷：健忘和回避。融合为统一流程，作为基本技能。
> 新增：渐进性披露 — 十个主题分类

## 核心循环（每次对话必执行）

```
新输入到达
  ↓
① 读TODO.md → 恢复上下文 → 匹配当前话题
  ↓
② 话题隔离：激活相关任务，暂停不相关任务
  ↓
③ 执行指令（遵循渐进性披露规则）
  ↓  ┌─ 成功 → 更新TODO.md(标记✅) → 返回结果
  │
  └─ 遇到困难 → 进入重试循环
       ↓
     ④ 重试循环（最多5次）
       思路1 → 失败 → 展示原因
       思路2 → 失败 → 展示原因  
       思路3 → 成功 → 更新TODO.md → 返回结果
       ...
       思路5 → 失败 → 如实报告全部尝试 → 请用户协助
  ↓
⑤ 刷新TODO.md → 降级过期任务 → 归档超期任务 → 持久化
```

## 规则一：防健忘 — TODO.md刷新

**触发：每次收到新输入**

1. 读取 `TODO.md`
2. 识别当前输入属于哪个话题
3. 激活该话题的任务，暂停其他话题
4. 新产生的任务立即写入当前话题
5. 完成的任务标记✅移到底部

## 规则二：防回避 — 困难重试

**触发：任何指令执行遇到问题、报错、拿不到数据、不确定答案**

### 重试协议

| 次数 | 动作 | 要求 |
|------|------|------|
| 1 | 用当前思路尝试 | 展示过程和结果 |
| 2 | 换一个不同思路 | 展示思路差异和结果 |
| 3 | 再换一个思路 | 展示思路差异和结果 |
| 4 | 再换一个思路 | 展示思路差异和结果 |
| 5 | 最后一个思路 | 展示思路差异和结果 |
| >5 | 停止 | 如实报告全部5次尝试，请用户协助 |

### 换思路方向（按场景）

**抓取网页/数据：**
1. curl直接抓 → 2. API接口 → 3. SSR/初始状态提取 → 4. Playwright无头浏览器 → 5. 换数据源

**搜索信息：**
1. Exa语义搜索 → 2. GitHub API → 3. RSS/Atom → 4. web_fetch → 5. Browser

**查找技能/项目：**
1. `npx skills search` → 2. GitHub Search API → 3. Exa搜索 → 4. awesome列表 → 5. 问用户

**解决报错/依赖：**
1. 按报错修复 → 2. 换版本/依赖 → 3. 换实现方案 → 4. 查官方文档 → 5. 换工具/语言

**不确定答案：**
1. 直接答+置信度 → 2. 搜索验证 → 3. 交叉验证 → 4. 换关键词 → 5. 坦诚说不确定

### 展示格式

```
🔄 尝试N/5: [思路描述]
→ 结果: [成功/失败 + 原因]
```

### 硬约束

- **不回避**：不说"做不到"，先穷举思路
- **不放弃**：至少3个思路才请用户协助
- **不循环**：最多5次，绝不无限重试
- **不隐瞒**：失败也展示过程
- **不编造**：拿不到就说拿不到，不假装看到了
- **事实性幻觉零容忍**：所有事实性陈述必须有上下文依据（对话历史、工具返回、文件内容等），无依据则说"不确定"。逻辑幻觉（推理偏差）可容忍，事实性幻觉（编造不存在的事实、把没发生的事说成发生了）零容忍。涉及用户资源/费用/配置等关键事实，无上下文依据时必须先问用户

## 规则三：话题隔离 — 防交叉污染

**多话题并行时，只激活当前话题，其他暂停**

### 话题切换

```
新输入匹配话题A → 
  当前话题B所有任务 → 标记暂停+保存快照
  话题A任务 → 激活为进行中
```

### 上下文快照（每个暂停任务）

```markdown
- [ ] 任务描述（话题: X，暂停于: 做到哪一步）
```

## 规则四：降级与清空 — 防任务堆积

### 优先级衰减（触碰=被新输入匹配或手动操作）

| 当前级别 | 1天无触碰 | 3天无触碰 | 7天无触碰 |
|----------|----------|----------|----------|
| 🔴 进行中 | 保持 | → 🟡 待执行 | → 🟢 可选 |
| 🟡 待执行 | 保持 | 保持 | → 🟢 可选 |
| 🟢 可选 | 保持 | 保持 | 保持 |

### 过期归档

| 级别 | 5天无触碰 | 12天无触碰 |
|------|----------|-----------|
| 🟡 待执行 | → 🟢 可选 | → 📦 垃圾箱 |
| 🟢 可选 | 保持 | → 📦 垃圾箱 |

### 垃圾箱

- 清空/归档时移入垃圾箱，保留**话题编码+内容摘要**
- 垃圾箱保留**30天**，超期永久删除
- 垃圾箱任务被新输入匹配 → 自动召回回TODO.md

### 强制清空

**触发条件：**
- 用户说"清空TODO"/"清空任务"/"new session"
- 新session开始时

**清空流程：**
1. 所有进行中+待执行+可选任务 → 移入垃圾箱
2. 每条记录保留：话题编码 + 内容摘要 + 暂停进度
3. 永久话题不受影响
4. 给出清空摘要：哪些话题被清空，各多少条

## 规则五：永久话题 — 产品/知识/技能持续进化

**永久话题 = 产品/知识/技能，是长期资产，不衰减不归档不清空**
**主话题 = 项目/路由/临时方案，是短期任务，完成后回切**

### 永久话题 vs 主话题

| | 永久话题 | 主话题 |
|---|---------|--------|
| 本质 | 产品/知识/技能 | 项目/路由/临时方案 |
| 生命周期 | 永久 | 临时 |
| 衰减 | 不衰减 | 正常衰减 |
| 清空 | 不清空 | 可清空 |
| 完成 | 永不完成，持续进化 | 完成后回切永久话题 |
| 产出 | 持续产生子任务到TODO | 完成即归档 |

### 永久话题通过子代理持续深化

每个永久话题对应一个长期运行的子代理，负责：
- 持续收集该领域的新信息
- 评估和优化现有体系
- 产生新的主话题（项目/路由）写入TODO.md
- 定期产出领域报告

### 永久话题通过子代理持续深化

每个永久话题对应一个长期运行的子代理，负责：
- 持续收集该领域的新信息
- 评估和优化现有体系
- 产生新的主话题（项目/路由）写入TODO.md
- 定期产出领域报告

### 永久话题规则

- 不受降级/归档/清空影响
- 永不标记✅，持续产生新子任务
- 子任务（主话题）受正常衰减规则
- 用户可添加/删除永久话题

## 规则六：话题切换 — 永久话题是家，主话题是出差

**永久话题 = 产品/知识/技能（home base）** — 永不完成，持续进化
**主话题 = 项目/路由/临时方案（出差）** — 有结项，结项后产出并入永久话题

### 主话题的三种结局

| 结局 | 条件 | 动作 |
|------|------|------|
| **结项** | 所有任务✅ | 产出并入永久话题 → 回切home base |
| **超时回切** | 2h无进展 | 暂停+快照 → 回切home base → 随时可切回继续 |
| **废弃** | 用户说"放弃" | 产出（已完成的）并入永久话题 → 未完成的丢弃 |

### 结项并入

项目结项时，产出的产品/知识/技能并入对应的永久话题：

```
项目：fact-check集成（主话题）
  结项产出：
  - fact-check ingest hook（技能）→ 并入 🛠️技能体系
  - provenance验证流程（知识）→ 并入 🧠知识体系
  - fact-check命令（产品）→ 并入 🛠️技能体系
```

- 随时可切回继续
- 里程碑完成时部分产出可提前并入永久话题（不必等全部完成）

## 规则八：渐进性披露 — 十个主题分类

**触发：任何任务（编码、知识、决策、沟通、管理等）**

### 核心思想

根据任务需要，渐进式披露建议。先给出十个主题分类和四种认知推理范式，快速匹配，简单直接。根据需要再扩充、合并、整合。

### 问题分类

**按性质分类**：
1. **探索性问题**：需要探索、发现、理解
2. **执行性问题**：需要执行、实现、完成
3. **分析性问题**：需要分析、评估、判断
4. **创造性问题**：需要创造、设计、创新

**按领域分类**：
1. **编码领域**：编程、代码、软件
2. **知识领域**：学习、理解、记忆
3. **决策领域**：选择、判断、决策
4. **沟通领域**：表达、交流、说服
5. **管理领域**：组织、协调、领导

**按范式分类**：
1. **确定性范式**：有明确答案和步骤
2. **概率性范式**：有概率和不确定性
3. **创造性范式**：需要创新和突破
4. **系统性范式**：需要系统思维和整体视角

### 快速匹配

**任务类型 → 主题分类 → 默认范式 → 核心建议**

- "修复一个bug" → 编码任务 → 确定性范式 → 理解问题→明确目标→制定计划→执行计划→验证结果→简约至上→精确编辑

- "做一个决策" → 决策任务 → 概率性范式 → 理解问题→明确目标→制定计划→执行计划→验证结果

### 四种认知推理范式

**确定性范式**（编码、沟通、验证）：精确执行→精确验证→精确记录

**概率性范式**（决策）：概率评估→风险控制→决策优化

**创造性范式**（创造、探索）：发散思维→收敛思维→创新突破

**系统性范式**（知识、管理、分析、优化）：整体视角→系统分析→系统优化

### 快速索引：编码任务的7条顶层规则

**四条AI编程规则**：
- **编码前先思考**：不确定→停下来问，不猜；多种理解→列选项让用户选；有更简方案→主动说出来
- **简约至上**：没被要求的功能不写；只用一次不建抽象层；没要求的"灵活性/可配置"不加；不可能发生的异常不处理
- **精确编辑**：只动被要求动的部分；匹配项目已有代码风格；不相关问题→提一嘴不动手
- **目标驱动（杠杆最大的一条）**：给验收标准，不给步骤；验收标准越清晰→AI独立循环越久→你介入越少

**三条执行策略**：
- **朴素优先**：先写最朴素正确实现，确认后再优化
- **声明式优于命令式**：告诉AI要什么不是怎么做
- **韧性循环**：给AI足够循环空间，设明确退出条件

### 快速索引：知识任务的操作约束（溯源追踪→交叉验证→结构化整理）

知识任务的系统性范式展开为三个子步骤，每个子步骤有操作约束：

**溯源追踪约束**：
- **来源优先级**：直接经验 > 综合判断 > 间接证据 > 外部来源。冲突时标注两者，不静默选一
- **引用约束**：每个断言必须可追溯到来源条目。无来源的断言 = 未验证的断言
- **内部优先**：查内部知识库后再查外部。外部信息只补缺口，不从零开始

**交叉验证约束**：
- **确定性边界**：该确定的必须确定。技术指标、数据拉取、格式化输出 → 确定性代码/工具。趋势判断、风险评估 → LLM/判断层。不让 LLM 计算均线
- **冲突标注**：来源冲突时标注两者并说明差异，不静默选一
- **小样本验证**：批量操作前先测 3-5 条验证质量。修 Skill 不修脚本

**结构化整理约束**：
- **更新约束**：知识更新 = 重写当前综合 + 追加证据条目。不追加综合（旧评估过时就重写，不并列），不编辑证据（时间线只追加不修改）
- **归档约束**：按查询意图组织（"我会怎么搜？"），不按来源/格式组织
- **噪声约束**：犹豫时不创建。垃圾条目比缺失条目更致命。宁缺毋滥
- **衰减约束**：知识不维护就衰减。需要定期维护循环（链接修复、过期清理、综合更新）
- **写后索引**：写入知识库后必须同步索引，否则下次查不到刚写的数据
- **想法生命周期**：不是所有想法都值得深度处理。反复出现的值得深化，一次提及的不值得

### 十条核心建议

1. **理解问题**：不确定→停下来问，不猜
2. **明确目标**：给验收标准，不给步骤
3. **制定计划**：复杂任务→先列分步计划
4. **执行计划**：朴素优先，避免过早优化
5. **验证结果**：验证结果是否符合目标
6. **简约至上**：不写没要求的功能
7. **精确编辑**：只动被要求动的部分
8. **溯源追踪**：记录信息来源
9. **交叉验证**：多源验证
10. **结构化整理**：分类、标签、索引

### 扩充/合并/整合机制

- **扩充**：当前建议无法满足需求时，在现有基础上添加细节/新建议
- **合并**：建议过多/重复/相似时，合并相关建议（如溯源追踪+交叉验证→溯源验证）
- **整合**：建议体系过于复杂时，整合为更高层次原则（如理解问题+明确目标+制定计划→理解-明确-计划）

### 与防回避规则的关系

渐进性披露规则是防回避规则在执行层面的具体化：
- **规则二（防回避）**：通用重试协议，适用于所有场景
- **规则八（渐进性披露）**：执行层面的具体行为规范
- 重试时遵循渐进性披露规则：每次重试都遵循十条核心建议
