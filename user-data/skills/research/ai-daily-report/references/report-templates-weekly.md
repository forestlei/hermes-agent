### Divide-and-Conquer Report Generation (周报/月报必用)

**问题**：周报聚合7天数据(~2.4MB)、月报聚合30天数据(~10MB)，单次生成会反复触发context压缩，导致信息丢失和重复压缩。

**解决方案**：将报告生成拆分为 **Phase 0 → Phase 1(并行) → Phase 2** 三阶段，每个子任务context独立且小。

#### Phase 0: 数据聚合（一次性，输出中间文件）

```bash
python3 ~/.hermes/scripts/aggregate-report-data.py --type weekly   # 自动取上周
python3 ~/.hermes/scripts/aggregate-report-data.py --type monthly  # 自动取上月
python3 ~/.hermes/scripts/aggregate-report-data.py --type weekly --week 2026-W15  # 指定周
```

输出到 `shared/reports/weekly/.draft/{period}-data.json`，同时拆分为：
- `{period}-papers.json` — 去重排序后的论文
- `{period}-projects.json` — 去重排序后的项目
- `{period}-news.json` — 新闻+feeds+每日统计

#### Phase 1: 主题分析（4个独立子任务，可并行，每个只读自己主题的数据）

每个子任务用 `delegate_task` 或独立 `execute_code` 执行，输出为 `.md` 文件：

| 子任务 | 输入 | 输出 | 说明 |
|--------|------|------|------|
| 论文分析 | `{period}-papers.json` | `{period}-papers.md` | Top20论文 + Top3深度分析 |
| 项目分析 | `{period}-projects.json` | `{period}-projects.md` | Top20项目 + Top3深度分析 |
| 新闻分析 | `{period}-news.json` | `{period}-news.md` | 行业大事件 + 严重度分类 |
| 趋势分析 | `{period}-data.json`(summary部分) | `{period}-trends.md` | 跨主题趋势 + 周度/月度对比 |

**关键约束**：
- 每个子任务只读取自己的数据文件，不读其他主题数据
- 每个子任务输出为纯Markdown，不含YAML frontmatter
- 每个子任务的context消耗控制在50K tokens以内
- 子任务之间无依赖，可完全并行

#### Phase 2: 整合（轻量，只读4个md文件）

```bash
python3 ~/.hermes/scripts/merge-report.py --type weekly --period 2026-W15
python3 ~/.hermes/scripts/merge-report.py --type monthly --period 2026-03
```

读取 `.draft/` 下的4个md文件 + data.json(概览统计)，合并为最终报告。

#### Cron执行流程（周报/月报prompt必须遵循）

```
Step 1: python3 aggregate-report-data.py --type weekly
Step 2: 并行执行4个主题分析子任务（delegate_task或顺序execute_code）
Step 3: python3 merge-report.py --type weekly --period {period}
Step 4: 发送最终报告
```

**禁止**：在单个agent loop中串行完成所有主题分析（必然触发压缩）
