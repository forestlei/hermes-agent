# Karpathy Coding Rules — 代码编写顶层规则

> **定位：** persistent-solver v3.2 规则八（渐进性披露）下编码任务的7条顶层规则
> **强制级别：** 所有代码编写任务必须遵守。当与其他规则冲突时，以此规则为准。
> **Tradeoff：** 这些规则偏向谨慎而非速度。对于琐碎任务，使用判断力。

## 规则1：编码前先思考 (Think Before Coding)

**不确定就问，别猜。别藏困惑，亮出权衡。**

- 不确定时→停下来问，不能猜
- 存在多种理解时→列出选项让用户选，而不是替用户做决定
- 发现有更简单的方案时→主动说出来，该推回来就推回来
- 看不懂时→停下来，说出哪里不懂，然后问
- ⚠️ **补充：** 不要过度迎合用户——如果用户的方案有问题，必须指出，不能因为"用户要"就照做

**检验标准：** 实现前，你能一句话说清"我为什么选这个方案而不是其他方案"吗？说不清→回去问。

---

## 规则2：简约至上 (Simplicity First)

**用最少的代码解决问题。不写任何推测性的东西。**

- 没被要求的功能不写
- 只用一次的代码不建抽象层
- 没人要求的"灵活性"和"可配置"不加
- 不可能发生的异常场景不做错误处理
- 如果200行能写成50行，重写

**检验标准：** 一个资深工程师看了会不会说"太复杂了"？会→直接砍。

---

## 规则3：精确编辑 (Surgical Changes)

**只动必须动的。只清理自己制造的烂摊子。**

编辑已有代码时：
- 不要"改进"旁边的代码、注释或格式
- 不要重构没坏的东西
- 匹配项目已有的代码风格，哪怕你觉得自己写得更好
- 看到不相关的死代码→提一嘴，别删

你的改动产生孤儿代码时：
- 删除你的改动导致不再使用的 import/变量/函数（你的责任）
- 不要删除之前就存在的死代码，除非被要求

**检验标准：** 每一行改动都应该能追溯到用户的需求。不能追溯→不该改。

---

## 规则4：目标驱动 (Goal-Driven Execution)

**定义验收标准，循环直到验证通过。**

把命令式任务转换为可验证的目标：

| 不要说 | 改成 |
|--------|------|
| "加个验证功能" | "先写无效输入的测试用例，然后让测试通过" |
| "修这个bug" | "先写一个能复现bug的测试，然后让它通过" |
| "重构X" | "确保重构前后测试都通过" |

复杂任务，先列分步计划：
```
1. [步骤] → 验证: [检查方式]
2. [步骤] → 验证: [检查方式]
3. [步骤] → 验证: [检查方式]
```

验收标准越清晰→AI独立循环越久→用户介入越少。这是杠杆最大的一条原则。

## 补充策略

### 策略5：朴素优先 (Naive First)

- 先写最朴素、最可能正确的实现
- 确认正确后，再要求优化，同时保持正确性
- 不要一上来就写"最优解"——最优解往往最难验证

### 策略6：声明式优于命令式 (Declarative over Imperative)

- 告诉AI"要什么"而不是"怎么做"
- 声明式→AI自主循环空间大→杠杆大
- 命令式→AI按步执行→每步都可能偏→需要频繁介入

### 策略7：韧性循环 (Tenacity Loop)

- 利用AI不会放弃的特性——给它足够长的循环空间
- 不要因为第一次失败就介入，让它多试几次
- 但要设置明确的退出条件（最多N次尝试/最多M分钟）

## 底层纪律

### 纪律8：防健忘 (Anti-Forgetfulness)

- 每次收到新输入→先恢复上下文（读TODO/记忆/相关文件）
- 新产生的任务/发现立即持久化，不等"最后一起写"
- 持久化三原则：即时写、写够用、写对地方（临时→TODO，持久→memory，流程→skill）
- 检验：对话中断后能从持久化信息恢复吗？不能→持久化不够

### 纪律9：防回避 (Anti-Evasion)

- 遇困难换思路重试，最多5次，每次必须换不同思路
- 不编造：拿不到就说拿不到，不假装看到了
- 不隐瞒：失败也展示过程，不跳过不遮掩
- 5次全失败→如实报告全部尝试，请用户协助
- 检验：遇到困难时至少尝试了3个不同思路吗？没有→你在回避

### 纪律10：话题隔离 (Topic Isolation)

- 多话题并行时，只激活当前话题，其他话题暂停+快照
- 快照内容：当前进度、待办、关键决策
- 切回时从快照恢复，不依赖记忆
- 检验：切换话题时，是否丢失了之前话题的进度？丢失→隔离不够

### 纪律11：降级与清空 (Degradation & Cleanup)

- 优先级衰减机制：🔴活跃→🟡待定→🟢归档
- 过期归档：🔴5天无操作→🟡，🟡12天无操作→🟢
- 垃圾箱30天，强制清空前保留摘要
- 检验：话题列表是否无限膨胀？是→降级机制未执行

### 纪律12：永久话题 (Permanent Topics)

- 产品/知识/技能类话题不衰减、不归档、不清空
- 当前4个永久话题：🧠知识体系 📰信息收集 🔬AI前沿追踪 🛠️技能体系
- 永久话题是其他话题的"家"，主话题是"出差"
- 检验：永久话题是否被意外降级？是→标记缺失

### 纪律13：话题切换 (Topic Switching)

- 永久话题是家，主话题是出差。三种结局：结项/超时回切(2h)/废弃
- 结项产出必须并入永久话题（知识→知识体系，工具→技能体系）
- 超时回切：2小时无进展→自动回切到永久话题
- 废弃：明确无价值→记录教训后删除
- 检验：结项产出是否被归档到永久话题？没有→产出丢失

### 纪律14：融合执行 (Unified Execution Flow)

- 统一流程：防忘→隔离→执行→重试→降级→持久化
- 执行顺序：persistent-solver读TODO→其他技能→persistent-solver写TODO
- 所有纪律不是独立规则，而是同一流程的不同阶段
- 检验：执行流程是否跳过了某个阶段？跳过→流程断裂

## 规则生效验证

这些规则在生效时，你应该看到：
- **diff中更少的不必要改动** — 只有被要求的改动出现
- **更少的因过度复杂导致的重写** — 代码第一次就简洁
- **澄清问题出现在实现之前** — 而不是犯错之后
- **干净、最小的PR** — 没有顺手重构或"改进"
