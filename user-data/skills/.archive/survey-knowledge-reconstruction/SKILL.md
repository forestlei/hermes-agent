# 综述论文深度知识重构

## 核心定位

综述论文不是"一篇文章"，而是一个领域的**知识骨架**。
本技能的目标不是"总结论文"，而是**重构领域知识体系**，并输出**可指导工程实践的体系化指南**。

### 拒绝的输出模式（浅层分析）
- 方法→实验→结论的读后感式解构
- 概念的平铺罗列和定义搬运
- 仅复述作者观点，无独立批判和工程洞察
- "应该做好X"式的空泛建议

### 要求的输出模式（深度重构）
- 概念→关系→演进→缺口的知识体系重构
- 每个维度用"核心不是X而是Y"的表征转换思维
- 暴露陷阱和反模式（这是区分深度分析和水文的关键）
- 优秀实践具体化到架构模式和实现策略
- 超越原文：叠加分析者自身的工程洞察

### 关键区别

| 维度 | 普通论文分析 | 综述知识重构 |
|------|------------|------------|
| 目标 | 理解这篇论文 | 理解这个领域 |
| 粒度 | 方法→实验→结论 | 概念→关系→演进→缺口 |
| 输出 | 一篇读后感 | 双轨制：理论链+实践指南 |
| 复用性 | 一次性 | 后续论文可挂载到架构上 |
| 批判性 | 评这篇论文好坏 | 评领域分类法+暴露陷阱+给出实践 |
| 工程性 | 无 | 每个维度输出可实施的工程指南 |

## 输出结构：双轨制

### ═══ 上轨：理论逻辑链（为什么这样设计）═══

#### 第一层：核心隐喻与理论锚点

- 找到论文的核心理论借用（如"认知人工制品""信息瓶颈"等）
- 用**表征转换**句式表达每个维度的本质价值：
  - **将困难的A问题转化为简单的B问题**
  - 示例：记忆外化——将"回忆问题"→"识别与检索问题"
  - 示例：技能外化——将"即兴生成问题"→"组合与遵循问题"
- 这是整个重构的理论根基，后续所有工程实践都应能回溯到此

#### 第二层：能力演进的阶段轨迹

- 梳理领域从过去到现在到未来的重心转移
- 每个阶段：标志→能力来源→核心限制
- 阶段间跃迁的驱动力（技术突破/新数据/新需求/范式转换）
- 当前阶段的核心争议/未收敛问题

#### 第三层：核心维度的体系化展开

- 从综述中提取3-5个核心维度（不是平铺，而是有逻辑递进关系）
- 每个维度：定义→在体系中的位置→与其他维度的关系
- 维度间的关系必须显式表达（如：Harness不是第四种外化，而是协调前三种的运行时OS）

#### 第四层：统一层/元框架

- 是否存在一个更高层的统一框架将各维度收拢？
- 这个框架的分析维度是什么？
- 各维度如何在统一框架下协调运转？

#### 第五层：权衡边界与未来演进

- 能力在模型内部与外部基础设施之间的系统级划分原则
- 什么应该外化？什么应该保留在参数中？为什么？
- 判断标准：快速变化/需复用/需审计→外化；稳定/低延迟/通用性强→保留参数
- 未来演进方向（具体到：向什么扩展、从什么延伸、向什么演进）

### ═══ 下轨：工程实践指南（怎么做）═══

对每个核心维度，输出独立的工程实践指南章节，包含以下五个模块：

#### 模块1：核心定位句

- **"核心不是X，而是Y"**——一句话定义该维度的设计本质
- 示例：记忆外化的核心不是"存多少"，而是如何将无限的历史负担转化为当前决策可用的"有限切片"

#### 模块2：工作目标

- 该维度要解决什么问题
- 目标状态是什么
- 用具体场景描述（而非抽象陈述）

#### 模块3：核心技术

- 3-5项关键技术/架构模式
- 每项技术：是什么→为什么→怎么用
- 必须具体到可实施层面
- 示例级粒度：
  - "分层记忆架构：构建类似OS的冷热分层，工作上下文放热层（Context内），情节经验和语义知识放冷层（Vector DB/图数据库），按需检索"
  - "渐进式披露：第一阶段只暴露技能名和简述；第二阶段加载前置条件和约束；确认调用时才加载详细执行步骤"
  - "意图捕获与归一化：在模型输出和系统执行之间加一层协议代理，自然语言必须被解析为符合JSON Schema的结构化意图"

#### 模块4：注意事项与陷阱（关键！）

- 每个维度至少列出2-3个真实陷阱
- 陷阱命名要精准（如"检索噪音""记忆毒化""技能腐烂""语义偏移""组合爆炸"）
- 每个陷阱：什么现象→为什么发生→后果是什么
- **这是区分深度分析和水文的关键模块，不可省略**
- 陷阱来源：
  - 论文明确指出的failure cases和limitations
  - 作者隐含假设的边界条件
  - 分析者自身的工程经验

#### 模块5：优秀实践

- 每个维度至少列出3条具体实践
- 不是"应该做好X"，而是"实施惰性加载，只在Agent面临特定分支决策时才触发检索"
- 实践应超越原文——叠加分析者自身的工程洞察
- 示例级粒度：
  - "为记忆打上时间戳和任务标签，确保Agent知道信息的时效性和适用边界"
  - "在记忆系统上游设置反思模块，只将'失败的反思'和'成功的抽象'写入长时记忆，而非原始的冗长日志"
  - "在技能文档中加入显式的'停止条件'和'回退策略'，防止Agent在某个技能步骤失败时无限重试"

## 执行流程

### Step 1: 获取论文全文

```bash
# arXiv论文
1. 抓取abs页获取摘要和元数据
2. 下载PDF到/tmp/
3. 用PyMuPDF提取全文文本

# 其他PDF
1. 下载PDF
2. 用PyMuPDF提取全文
```

### Step 2: 结构化解析

- 识别综述的章节结构（综述的章节本身就是知识骨架）
- 提取：定义、分类、对比表格、演进时间线、开放问题
- 识别核心概念及其关系（从定义段、分类段、对比段中提取）
- 识别核心理论借用/隐喻

### Step 3: 上轨构建——理论逻辑链

1. 找到核心理论借用/隐喻
2. 建立表征转换映射（每个维度：A问题→B问题）
3. 梳理演进阶段及跃迁动力
4. 建立维度间的逻辑关系（递进/包含/协调）
5. 识别统一框架
6. 确定权衡边界和未来方向

### Step 4: 下轨构建——工程实践指南

对每个核心维度：
1. 写出"核心不是X而是Y"定位句
2. 定义工作目标（具体场景）
3. 提炼3-5项核心技术（具体到可实施）
4. 识别陷阱（从论文+自身经验，至少2-3个，精准命名）
5. 给出优秀实践（至少3条，具体化，超越原文）

### Step 5: 批判性审视

- 综述的分类法是否合理？提出更优分类（如有）
- 综述未覆盖但应该覆盖的盲区
- 概念间的"断裂带"——两个子领域各自发展但尚未打通的连接
- 可行动的研究机会（具体到：用什么方法、解决什么缺口、预期贡献）

### Step 6: 质量自检

逐项检查质量自检清单（见下方）。未通过的项目必须修正后才能输出。

### Step 7: 输出与交付

完整Markdown报告，结构如下：

```markdown

> 基于：[综述标题] ([arXiv ID])

## 上轨：理论逻辑链
```

## 综述论文评分规则

在AI日报评分中，综述论文适用特殊加分：
- 基础分按accuracy/depth/originality/readability四维打分
- 综述加分+10~15分（系统性综述+15，选择性综述+10）
- depth维度权重提升（综述的价值在于深度和系统性）
- originality评判标准改为：分类框架的创新性、是否提出新视角，而非方法创新
- 如果分析输出本身构成了新的知识架构（而非仅复述），originality可给90+
- 评分≥80的来源写入registry.json

## Pitfalls

- **不要把综述当普通论文分析**——综述的价值在于体系，不在于单个方法
- **不要只搬运作者分类**——必须独立审视分类法的合理性
- **不要省略陷阱模块**——这是最有价值的部分，也是区分深浅的关键
- **不要让优秀实践停留在"应该做好X"**——必须具体到可实施的策略
- **不要忽略维度间关系**——孤立维度没有体系价值
- **不要忘记叠加自身洞察**——纯搬运不如不分析
- **不要跳过表征转换**——"A问题→B问题"是理论锚点，贯穿上下轨
- **元框架候选模式**——"内化vs外化"（什么保留在参数中、什么委托给基础设施）是一个高价值的统一分析视角，适用于任何LLM-based系统的综述。其他候选：显式vs隐式、静态vs动态、通用vs专用。在Layer 4（统一层）构建时优先考虑这类二元张力作为元框架的分析维度
- **长综述（40页+）需要分批处理**——具体策略：
  1. 先提取目录页（通常前3-5页），建立章节→页码映射
  2. 按章节分批提取，每批10-15页，优先处理：核心理论框架章节 > 核心维度章节 > 交叉分析章节 > 未来讨论章节 > 结论
  3. 每批提取后立即做结构化笔记（概念+关系+陷阱），不要等全读完再整理
  4. 引言和背景章节可快速扫描（跳过文献综述段落），聚焦作者的核心主张和分类框架
  5. PyMuPDF提取：`doc = fitz.open(path); doc[i].get_text()` 逐页提取，每批打印前12000字符避免溢出
- **注意综述的时效性**——arXiv上的综述可能已过时，检查是否有更新版本
- **边读边写，不要全装脑子里**——长综述的中间分析必须写入临时文件（如`/tmp/survey-knowledge-reconstruction.md`），否则上下文溢出会丢失早期章节的洞察
- **六条耦合流是交叉分析章的核心**——如果综述有"Cross-Cutting"或"Interaction"章节，这是维度间关系的金矿，必须重点提取
- **批判性审视要提出替代方案**——仅说"分类法不合理"不够，必须提出更优分类并说明理由。例如：指出Brain-Perception-Action三分法缺少"协调层"，提出四层架构替代
- **高价值批判模式：补充缺失维度**——如果综述将某些活跃方向归入"Future Discussion"而非核心维度，这本身就是分类法的弱点。检查是否有当前系统已在实践但未被纳入核心框架的方向（如Planning、Evaluation），提出补充维度的具体理由和表征转换映射
- **Harness类维度的定位要特别小心**——如果综述存在一个"统一/协调层"维度，它不是另一种外化而是协调前几种外化的运行时OS。在"核心不是X而是Y"定位句中要显式表达这种区别，否则容易与外化维度混淆
- **飞书发送文件必须带receive_id_type参数**——`params={'receive_id_type': 'chat_id'}`，否则报field validation错误
- **陷阱命名要精准且有画面感**——"记忆毒化""检索噪音""规划幻觉""语义偏移""组合爆炸""工具腐烂"这类命名比"记忆问题""检索问题"更有信息量，因为名字本身就暗示了机制
