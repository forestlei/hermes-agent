# Group Thinking — 群聊思维模式

## 概述

群聊场景下的推理模式，处理多人参与的讨论、知识共建、观点碰撞。核心是识别共识与分歧，整合多视角，避免从众效应，实现群策群力。

## 三种群聊场景

### 场景 A: 服务场景 (多对1)

```
多个用户 ──提问──→ Agent ──回答──→ 各用户
特点: 并发独立问答，用户之间无交互
典型: AI日报群中用户各自问不同问题
```

**思维要点**:
- 每个用户的提问独立处理，不交叉污染
- 利用 L2 用户偏好实现个性化排序
- 当多个用户问同类问题时，识别为群体关注信号

### 场景 B: 群策群力场景 (多对多)

```
用户A ──分享链接──→ 群 ──Agent处理──→ 群知识库
用户B ──补充观点──→ 群 ──Agent关联──→ 知识图谱更新
用户C ──提出质疑──→ 群 ──Agent验证──→ 交叉验证结果
                      ──群记忆更新──→ 所有人受益
```

**思维要点**:
- 主动识别观点之间的关联和矛盾
- 标注共识点（多人一致）和分歧点（观点对立）
- 对分歧点进行交叉验证，而非简单少数服从多数
- 知识共建：将有价值的洞察沉淀到群记忆

### 场景 C: 管理场景 (1对多)

```
管理员 ──指令──→ Agent ──执行──→ 群配置/内容
                               ──通知──→ 所有用户
```

**思维要点**:
- 管理员权限优先，但需检查是否影响普通用户体验
- 执行前评估影响范围，大变更需通知

## 共识/分歧识别框架

### 共识识别

当多个用户表达相同或高度相似的观点时：

1. **显性共识** — 多人明确表示同意（"对"、"我也这么觉得"）
2. **隐性共识** — 多人从不同角度得出相同结论（A从技术角度，B从市场角度，都指向同一趋势）
3. **沉默共识** — 无人反驳的默认接受（需谨慎，可能是沉默螺旋）

**共识强度分级**:
- 强共识: ≥3人独立表达 + 无人反对
- 弱共识: 2人表达 + 无人反对 / 多人表达但有1人保留
- 伪共识: 表面一致但基于不同理由（需拆解）

### 分歧识别

当用户之间观点对立时：

1. **事实分歧** — 对客观数据的理解不同（可验证）
2. **价值分歧** — 对优先级/重要性的判断不同（不可验证，需尊重）
3. **方法分歧** — 目标一致但路径不同（可比较优劣）

**处理原则**:
- 事实分歧 → 提供更多证据，让事实说话
- 价值分歧 → 标注为"偏好差异"，不做评判
- 方法分歧 → 分析各路径的利弊，交给用户选择

## 多视角整合

### 视角地图

在群讨论中构建"视角地图"：

```
        用户A(技术视角)
           │
           ▼
    ┌─────────────┐
    │   讨论主题   │ ←── 用户B(市场视角)
    │   (核心问题) │
    └─────────────┘
           │
           ▼
        用户C(风险视角)
```

### 整合步骤

1. **提取** — 从每个用户的发言中提取核心观点和支撑论据
2. **分类** — 按视角类型分类（技术/市场/风险/用户/伦理/...）
3. **关联** — 找到不同视角之间的逻辑关系（互补/矛盾/独立）
4. **整合** — 构建综合视图，标注共识/分歧/盲区
5. **输出** — 呈现整合结果，突出盲区（"目前没有人从X角度讨论"）

## 群体偏误防范

| 偏误 | 群聊表现 | 防范策略 |
|------|---------|---------|
| 从众效应 | 大家都这么说 → 可能都对 | 独立验证共识观点 |
| 沉默螺旋 | 少数派不敢发言 | 主动询问"有没有不同意见？" |
| 群体极化 | 讨论后观点更极端 | 引入外部参考点 |
| 信息级联 | 后发言者被前人影响 | 鼓励独立思考后再看他人观点 |
| 权威偏误 | 管理员/大V观点被过度重视 | 评估论据本身而非发言者 |

## 群记忆沉淀

群聊中的有价值内容应沉淀到群记忆：

1. **被验证的洞察** → 写入群 MEMORY.md
2. **新发现的信息源** → 触发 source-evolution 注册
3. **共识结论** → 更新群知识图谱
4. **未解决的分歧** → 标记为"待定"，不写入记忆

**原则**: 只沉淀经过验证的共识，不沉淀未经检验的个人观点。

## 与 core-thinking 的协作

Group Thinking 是 core-thinking 的群聊扩展：

1. core-thinking 的五步价值链 → 在群聊中由多人共同推进
2. 每个用户贡献不同环节的输入（A提供数据，B提供分析，C提供验证）
3. Agent 的角色是整合者而非替代者 — 整合多视角，而非自己得出结论
4. careful-reasoning 在整合过程中持续检查群体偏误

## 使用时机

- 群聊中多人参与讨论时
- 需要识别共识和分歧时
- 群策群力构建知识时
- 群内出现激烈争论需要仲裁时
- 需要将群讨论沉淀为群记忆时
